Foundations · Colors

          
Color tokens — proposed vs. current.

          
The proposed system: 13 tonal ramps generated in OKLCH for perceptually-even steps, aliased into role tokens (--ds-primary-*, --ds-secondary-*), then a status semantic layer on top. This page maps every proposed value back to the corresponding neo-design token it replaces.

        


        

          How to read this page. The proposed ramp set has been reconciled with the current DS semantic system: orange, cyan, indigo, pink dropped (no semantic role, not in the M-FISH brand). Ten tonal ramps remain — all 6 M-FISH brand strands (lime, green, teal, blue, violet, magenta) get full 10-step ramps with the exact brand-bright and brand-deep sitting inline as one stop each. Where a semantic alias would have hit a brand-exact stop, it's been shifted to the neighbouring stop so semantic tokens never equal a brand-bright or brand-deep hex (noted per-row in the comparison table).

Summary of the shift
what changes for consumers

          

            Structural. Consumers stop referencing raw ramps (digital-blue-500) directly; every UI role reads a semantic token (--ds-primary, --status-error-default). The ramps become the shared vocabulary the semantics are wired into.
          

          

            Ramp set. 10 tonal ramps: neutral, warm-grey (structure) · red, gold (error, warning) · lime, green, teal, blue, violet, magenta (the 6 M-FISH strands — green/blue back success/info, teal backs primary, violet backs active/queued, lime/magenta stay as brand accent). Orange · cyan · indigo · pink dropped (no semantic use, not in brand).
          

          

            Brand. The Digital Blue #2f42ff steps out of the primary role. Teal (#19756b light / #16a89b dark) becomes the default primary. All 6 M-FISH strands appear as one exact hex inside their tonal ramp (bright / deep ribbons at the closest position). Brand strand swatches live on the main Foundations page.
          

          

            Status. Success · Warning · Error · Info stay 4-part but hit stronger saturation and AA-safe stops. Active, Queued, Canceled land as first-class status semantics (they were ad-hoc activity/* hex values before).
          

          

            Brand ↔ semantic isolation. No semantic token resolves to a brand-bright or brand-deep hex. Where the natural ramp stop was a brand override (e.g. status-info-default → blue-600 = brand-bright), the semantic alias shifts to the neighbouring stop (blue-700). This holds in both modes and keeps the brand palette visually distinct from status colour.
          

          

            Dark mode. Status semantics now flip stops (light ← 900, default ← 500, dark ← 300) rather than remap to a different hex — mode-swap keeps the same visual language.
