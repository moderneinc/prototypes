System Design

Principles

Code is the source of truth. Figma is bidirectional. Anyone can contribute.

  • Production-first. Tokens are semantic intent in code — not visual values projected from a design tool. The repo is the authority. Figma, the CLI, and this site all read from it.
  • Bidirectional Figma. A plugin pushes canonical to Figma. Claude reads Figma via MCP and pulls changes back. Token-level edits flow in both directions. Structural changes go through the mirror/review flow.
  • Governed creativity. 30 composition rules enforce consistency. When Claude builds a new screen, it checks existing patterns first. If nothing matches, it generates the screen AND a draft set of rules — both go through review before becoming canonical.
  • Context survives the export. A color isn’t just #f87171 — it carries what it’s for, where it applies, and the evidence behind it.

Three layers

Everything in the system is organized into three layers. These are the same in code, in Figma, and on this site.

TOKENS
Colors, typography, spacing, glyphs, links. The atomic values everything else is built from.
COMPONENTS
Rows, sections, banners. Building blocks composed from tokens.
PATTERNS
Full screens like help, error, progress, success. Each generated from a canonical pattern file.

Composition rules

30 machine-readable rules in composition.json govern how screens are built. They enforce glyph-color pairing, semantic color limits, section ordering, and required elements per pattern type.

EXAMPLES
✓● must be red (danger sections) or white (action headers)✓Max 3 semantic colors per screen✓Error pattern requires WHAT WENT WRONG + TRY + close banner✓Close banner color must match exit condition✓Cyan is only for commands, flags, and paths
ENFORCEMENT
✓Build time: mirror items linted before baking into plugin✓On demand: npm run lint:composition✓Claude reads composition.json before generating any screen✓Mirror page shows lint results as badges per frame✓Screen gaps auto-detected from screens.json

Mirror: how new patterns enter the system

New screens don’t go straight to canonical. They land on a staging page in Figma for review before promotion.

PROPOSE
Write a .md file to design-system/mirror/
LINT
Build validates it against composition rules
REVIEW
Appears on Figma Mirror page with lint badge
PROMOTE
Move to patterns/, rebuild — now canonical

Gaps are detected automatically. Screens defined in screens.json that lack a pattern get NEEDS PATTERN stubs on the Mirror page.
