Tokens

Six token groups. Each is rendered as the thing it controls — color swatches show the color, type specimens show the typography, glyphs show the actual character — with provenance (role, evidence, applies_to) surfaced alongside.

Color

Semantic color tokens. Every color encodes a meaning; no token is decorative. Source values come from the journey-map CSS terminal classes (.t-cyan, .t-green, etc.). Single yellow token is shared across six expressions per D-03; disambiguation is by glyph + leading word + position, not by additional color.

Fallback policy

truecolor

Use the hex values above directly (24-bit ANSI escape).

xterm_256

Approximate to the nearest xterm-256 index. (Indices are framework-determined; visual system does not pin them.)

no_color

Emit no color escapes. Glyph + leading word + position carry the semantic. Banner phrases (MOD SUCCEEDED / MOD FAILED) remain bold; sectionizer characters (●, ▶, ✓, ⚠, ?, !) print as ASCII fallbacks per the glyph table.

Glyphs

Glyphs are paired with color tokens (color.semantic.*). Every glyph has an ASCII fallback (S). Glyph + color + leading word + position together discriminate semantically — no token relies on color alone.

Glyphs are stored as the terminal-native terminal.glyph type with {char, asciiFallback, role, color}. They flatten to a plain string only in the projected DTCG file.

Links

Hyperlink rendering rules per Q. Cyan text via color.semantic.info; underline is left to the terminal's link-rendering preference.

Policy

transport
OSC-8 escape sequences (existing AdvancedLinks.A / link helpers).
color
color.semantic.info
underlinePolicy
The CLI does not impose an underline. Terminals that render OSC-8 links with their own underline are honored; terminals that don't are not compensated for (no fallback bracket form).
fallback
When OSC-8 is not supported (terminal capability), emit plain cyan text without escape codes. No bracket / parenthesis fallback.
