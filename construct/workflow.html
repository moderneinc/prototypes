Getting started

One-time setup. These are the only terminal commands you’ll ever run. After this, Claude handles everything.

  1. Clone the repo and install:
    npm install
  2. Start the playground:
    npm run dev
    Open http://localhost:3000.
  3. Open the Figma file: CLI Design System Experiment
  4. In Figma desktop: Plugins → Development → Import plugin from manifest → select lib/interpreters/figma-plugin/manifest.json
  5. Run the plugin: Plugins → Development → Construct → click Initialize

That’s it for terminal. After this, you work in Claude Code and Figma only. Claude runs all builds, syncs, and validations for you.

WANT TO EXPERIMENT? SET UP A SANDBOX FIRST

Create a fresh copy so demos don’t touch your main workspace:

git worktree add demo origin/main && cd demo && npm install && npm run dev

When done, clean up:

cd .. && git worktree remove demo

Workflows

Four scenarios. Each can start from Figma or from Claude Code. You never need a terminal — say it to Claude, and Claude does it.

PULLABLE (PROPERTY EDITS)
Colors, fonts, glyph characters, banner phrases, padding.
STRUCTURAL (NEW COMPONENTS OR LAYOUT)
New patterns, new sections, rearranging composition.

1. Edit an existing token or property

Change a color, font size, glyph, banner phrase, or spacing value.

Change the value (in Figma or tell Claude)
│
Claude syncs it
│
Open Figma → Plugins → Development → Construct → Apply
│
Done
START IN FIGMA
Change a property in Figma. Claude reads it and updates the source files.
START IN CODE
Tell Claude what to change. Claude edits the file and rebuilds.

2. Create a new token

Propose a token that doesn’t exist yet. Goes through the mirror for review.

Tell Claude what you need
│
Claude writes a proposal to mirror/
│
Open Figma → Apply → review on Mirror page
│
Approve or Reject → tell Claude
START IN FIGMA
You need a color or glyph that doesn’t exist. Tell Claude.
START IN CODE
Tell Claude to write the token proposal directly.

3. Edit a pattern’s structure

Add, remove, or reorder sections in an existing pattern.

Describe the change to Claude (or share a screenshot)
│
Claude edits the pattern and rebuilds
│
Open Figma → Plugins → Development → Construct → Apply
│
Done
START IN FIGMA
Describe the change to Claude and Claude will make it. Or: duplicate the component in Figma, edit it visually, and share a screenshot with Claude — Claude will update the pattern to match.
START IN CODE
Tell Claude what to edit. Claude validates against composition rules.

4. Create a new pattern

Build a new CLI screen. Goes through the mirror for review.

Tell Claude what you need (or share a screenshot)
│
Claude writes the pattern and rebuilds
│
Open Figma → Apply → review on Mirror page
│
Approve or Reject → Claude promotes or revises
START IN FIGMA
Design the screen in a separate Figma file or scratch page, then share a screenshot with Claude. Claude generates the pattern spec from your design and validates it against the composition rules.
START IN CODE
Describe the screen to Claude. Claude writes the spec.

All commands

Say these to Claude. Claude runs everything — you stay in Claude Code and Figma.

status

pull from Figma

approve <name>

check mirror
Promote approvals, revise rejections, report status
demo 1 / 2 / 3 / 4

end demo
